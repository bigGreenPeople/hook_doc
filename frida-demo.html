frida-core

Vala 为主，配合 C/C++ 和平台代码。

Core 原生库
电脑端和手机端各有一份 Core。电脑端负责发请求和管理会话，手机上的 frida-server 使用 Core 处理请求。
自己写 Python 时，直接 import frida。Python 会在同一进程内加载 _frida.pyd。本机 Windows 版 16.4.7 把 Core 静态链接进了这个原生扩展。
device.attach(pid) → _frida.pyd → frida_device_attach_sync()
查看 Python 调用链
frida-server 可执行文件
在 Android 上启动后有自己的 PID。它接收电脑的请求，枚举应用、附加到指定 PID，并在需要时加载 agent。
agent 共享库（.so）
设备端收到附加请求后，按需把 agent 加载进目标 App 的 PID。agent 接收 hook.js，管理脚本的加载和卸载，并把消息传回电脑。
按 16.4.7 的默认构建，Gum 和 GumJS 的机器码已静态链接进 agent .so。agent 直接调用其中的 GumJS 来执行脚本，Java bridge 再与 ART 交互，安装 Java hook。
查看 agent 加载后的分工

可集成到自有 Android App 的测试版。由 App 自己加载，在同一 PID 内初始化 Frida，再等待电脑连接或按配置执行脚本。这种用法无需单独启动 frida-server。

Frida 用什么写，构建后在哪里运行

顶层仓库用 Meson 组织构建。命令行用 Python，Core 主要用 Vala，Gum 和 GumJS 主要用 C/C++。Vala 先生成 C，再编译、链接成原生程序或库。下表列出这条 Windows 到 Android 链路的主要产物。顶层构建文件 · Core 构建配置

看 PID 就能分清它们。 Windows 上的 frida 命令进程加载 _frida.pyd。Android 上启动 frida-server 会产生一个独立进程。agent、Gum 和 GumJS 则在目标 App 已有的 PID 里运行。

组件语言与技术构建或打包产物运行位置运行时负责什么
Frida CLI Python frida-tools Python 包及 frida 命令入口 电脑的命令行进程 解析参数、读入脚本、显示日志。
Python 绑定 Python 和 C 扩展 Python 包和 Windows 上的 _frida.pyd，扩展在构建时链接 Core。 Windows 上的 CLI 进程，由 Python 解释器加载。 把 CLI 的 Python 调用交给 Core 的原生接口。
Frida Core Vala、C 和 C++ 原生 Core 库，被链接进客户端绑定和服务端程序。 电脑上的 _frida.pyd 和手机的 frida-server 里。 电脑端发请求、管理会话；设备端枚举应用并处理附加。
frida-server Vala，调用 Core 针对设备架构构建的 Android ELF 可执行文件。 由 Android 启动，使用自己的 PID。 接收电脑请求，枚举应用，按 PID 附加并按需加载 agent。
Frida agent Vala，链接 Gum 和 GumJS Android 原生共享库（.so）。 由设备端 Core 加载进目标 App 的 PID。 接收脚本和控制消息，管理脚本的创建、加载和卸载。
Gum C/C++ 原生插桩库，默认构建中静态链接进 agent .so。 目标 App 进程内，运行的是 agent .so 中的 Gum 代码。 实现原生函数拦截、指令跟踪和内存查询。
GumJS C/C++，按构建使用 QuickJS 或 V8。 原生脚本绑定库，默认构建中静态链接进 agent .so。 目标 App 进程内，由 agent 直接调用。 通过 JS 引擎执行 hook.js，把 Gum 的能力提供给 JavaScript。
Java bridge JavaScript，通过 JNI 和 ART 接触 Java 运行时。 独立的 JS 包。Frida 17 起，CLI 和 frida-trace 预装 bridge，自定义 agent 可按需引入。 目标 App 的进程内 提供 Java.use() 等接口，将 ART 方法调用接到 JS 回调。
Frida Gadget Vala 及原生库 可嵌入应用的共享库，Android 上为 .so。 加载 Gadget 的 App 内 应用加载它时，在进程内启动 Frida 运行时。

安装 frida Python 包后，你自己的脚本可以直接 import frida，并用 Device、Session 和 Script 这些公开接口。CLI 也通过这套接口调用 Core。

你的 Python 脚本

  → _frida.pyd 原生扩展

App 进程内各模块的源码

agent 的 .so 加载后做什么

在这个 Server 模式的例子里，frida-server 收到附加请求后，按需把 agent 共享库加载到目标 App。agent 随后在 App 的 PID 内运行。加载和管理 hook 脚本是它的主要职责之一。

构建时，16.4.7 默认把 Gum 和 GumJS 静态链接进 agent .so。运行时，设备端先加载 agent .so，然后 agent 调用库内的 GumJS 加载并执行 hook.js。默认链接方式 · agent 构建定义

  1. agent 管脚本。 它接收电脑发来的 hook.js 源码，管理脚本的创建、加载和卸载，并经会话把日志传回电脑。
  2. GumJS 跑脚本。 agent 把源码交给 GumJS，后者通过 JS 引擎执行 hook.js。
  3. Java bridge 接到 Java 方法。 脚本调用 Java.use() 时，bridge 与 ART 交互。给 .implementation 赋值时，bridge 安装 onResume() 的 hook。
  • Frida agent来自 frida-core。lib/agent/agent.vala 管理 App 里的 agent 会话，script-engine.vala 接收脚本源码并通过 Gum 的脚本后端创建和加载脚本。打开 agent 会话 · 创建脚本
  • GumJS位于 frida-gum/bindings/gumjs/，负责提供 Frida 的 JavaScript 运行时接口。此版本通过 runtime/java.js 加载 Java bridge，runtime/console.js 把 console.log() 编成返回电脑端的消息。Java bridge 入口 · 日志编码
  • Java bridge把 JS 调用接到 Android 的 Java 环境。index.js 实现 Java.perform()，class-factory.js 创建 Java 方法的 JS 包装并处理 .implementation，lib/android.js 的 ArtMethodMangler 实现 ART 上的方法替换。Java.perform() · 方法包装与回调 · ART 适配
  • ART是 App 进程里原有的 Android 运行时，源码属于 AOSP。runtime/art_method.h 定义 Java 方法的运行时表示，Activity.java 定义本 Demo 观察的 onResume() 生命周期方法。AOSP ArtMethod · AOSP Activity

最小 Android Hook Demo

下面的 hook.js 以源码形式加载到测试 App 内的 JS 引擎，观察 Activity.onResume()。

Java.perform(() => {
  const Activity = Java.use('android.app.Activity');
  const onResume = Activity.onResume.overload();
  onResume.implementation = function () {
    console.log('onResume called');
    onResume.call(this);
  };
});

运行

在设备上启动已配置 Frida 的自有测试 App。将上面的代码复制到 hook.js，在该文件所在目录运行以下命令，并将包名替换成你的 App 包名。

frida -U -N com.example.demo -l hook.js

执行这条命令时发生了什么

  1. -U 选择 USB 设备，电脑上的 Frida 客户端连接设备上的 Frida 服务。
  2. -N com.example.demo 按包名找到已经运行的 App，并附加到它的进程。App 需要提前启动。
  3. -l hook.js 读取电脑上的脚本，把它加载到 App 进程内的 Frida agent。Java.perform() 的回调执行时，会装上 onResume() 的 hook。
  4. 把 App 切到后台再切回来。Activity 调用 onResume() 时，回调先记录 onResume called，再调用原方法。Frida 把日志传回电脑终端。

原理

Java.perform() 让脚本在可访问 Android Java 运行时的上下文中执行。Java.use() 找到 Activity 类，.implementation 把方法入口接到 JS 回调。回调先打印日志，再用 onResume.call(this) 调用原方法。
