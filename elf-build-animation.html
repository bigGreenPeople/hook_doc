亲眼看两份 .c 源码怎么变成 Android .so（ELF）

把复杂的编译链接拆成最直观的两幕：第一幕（1–4 步）看 foo.c 如何被翻译成留满“地址空坑”的 foo.o（ET_REL）；第二幕（5–8 步）看链接器 lld 如何合并 foo.o + bar.o——把内部调用 bar_helper 当场填死，把外部调用 __android_log_print 甩进 .got/.plt/.rela.plt 留给 dlopen，最终按权限打包 PT_LOAD 产出完整的 libdemo.so（ET_DYN）！

本动画示例源码（foo.c + bar.c） 含 1 次内部调用 + 1 次外部库调用 
// foo.c
int g_base = 10;                  // → .data
int g_count;                      // → .bss (磁盘0字节)
int demo_add(int x) {
    int t = bar_helper(x);        // ① 同工程 bar.c (内部)
    __android_log_print(3, "Demo", "%d", t); // ② liblog.so (外部)
    return t + g_base;
}
// bar.c
int bar_helper(int x) { return x * 2; }

一句话看懂整部动画：

      
① .c → .o（编译器 + 汇编器）是“各扫门前雪”——每个 .c 单独翻译成 ET_REL 格式的 .o，不认识别的文件里的函数，所有外部调用先在机器码里填 0 占坑，记进 .rela.text；此时还没有 Program Header，不能直接加载运行。

      
② .o → .so（链接器 lld -shared）是“总装出厂”——把所有 .o 的同类节合并，同工程内部调用（bar_helper）当场算出偏移填死；跨库外部调用（__android_log_print）则造出 .plt/.got/.rela.plt + .dynamic (DT_NEEDED) 留给运行期 dlopen 填空；最后按 R / R-X / RW 权限打成 PT_LOAD 写进 Program Header，一个完整的 ET_DYN 动态库 ELF 就诞生了！
